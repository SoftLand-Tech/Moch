1

Download the current beta.

Use the current CI beta APK for the embedded runtime. This is the build the rest of this guide describes.

Android beta 1.0.53-beta.3
Build 58 · served at /Moch.apk

Official main CI builds use the stable Moch signing key when repository secrets are configured, so they install over previous official builds. A fork or unconfigured run may use a different key and require uninstalling first. Android may warn because the APK does not come from an app store.

Download APK
  1. Open the downloaded .apk and allow Android to install it when asked.
  2. Open Moch. Do not use Expo Go for this flow; it does not include the native embedded-runtime bridge.
  3. For build history and checksums, open GitHub Releases.

There is no iOS release. Stable v1.0.0 is a legacy linked/relay-only build. It does not contain the embedded runtime or OpenCode and is not the download for this guide.

2

Choose the environment.

A Linux guest is a little Ubuntu computer inside Moch. It is optional for Hermes and required for OpenCode.

Hermes-only route

Skip Linux

Choose Skip when you only need Hermes. The embedded Hermes runtime does not need the Ubuntu guest. Terminal and Linux tools will not be available without it.

OpenCode + Linux tools

Install Ubuntu 24.04

Keep the default guest selection and let Moch download and prepare it. OpenCode runs inside this guest, alongside terminal tabs and project working directories.

This step uses the internet. Linux, OpenCode and package downloads are part of the setup. A local model later can run on-device, but Moch does not bundle local model weights.

3

Choose the thinker.

The thinker is the brain that answers. Moch (Hermes) is the default; OpenCode is an optional coding-agent thinker.

Default · no Linux required

Moch (Hermes)

Runs embedded. Choose it for the full Moch feature surface: Chat, Projects, Fleet, Crew, Automations, Skills, Connectors, Terminal, Browser and Inbox.

Optional · Linux required

OpenCode

Downloads from opencode.ai into Moch Linux on first selection. Keeps Chat, Projects/OpenCode sessions, Terminal, Browser and Settings; Hermes-only surfaces are hidden.

OpenCode is not bundled, default or official. Moch integrates it as a selectable thinker; Moch is not the official OpenCode app. Existing chats keep the thinker they were created with, and switching affects new chats.

4

Connect a model provider.

A provider is the service that runs the model. Choose a hosted provider or point Moch at a local model endpoint.

  • Hermes + a hosted provider

    Choose a provider in Moch and paste its API key when requested. The provider may require an account and charge for usage. Model inference travels over the internet.

  • OpenCode free hosted models

    OpenCode offers hosted models that need no key or account. “Free” does not mean on-device: these models still use the network.

  • A local model endpoint

    Connect a compatible model server for on-device inference. You bring the model and endpoint; Moch does not bundle local model weights. Downloads, OTA, browsing and optional tools may still use the internet.

Pick the model after the provider. Model catalogs may use the internet. If a hosted request fails, check the provider key, account and usage limits before changing the thinker.

5

Finish “About you”.

Give Moch enough context to be useful, choose your language, then review notification and battery permissions.

  • About you: add your name and a short note about what you want help with. Keep it minimal if you prefer.
  • Language: Moch ships English, Arabic with RTL, Chinese and French.
  • Notifications: allow local notifications if you want questions and finished work to reach you. Push registration can use the internet.
  • Battery: review Android’s battery restrictions if the runtime stops in the background. Local work still depends on the app process and runtime surviving.

You are ready for the first chat.

Start with a small task. Moch keeps the control plane and workspace on the phone; the model and tools decide what uses the network.

See the five-step method

If something does not work.

Start with the step where the problem appeared. Most setup failures are a blocked download, a missing provider or an Android permission.

Android blocks the APK install

Allow installs from your browser or file manager when Android asks, then reopen the APK. If the package will not replace an older build, compare the signing and version on GitHub Releases rather than installing stable v1.0.0 over the beta workflow.

Ubuntu or OpenCode will not download

Check the internet connection and available storage, then retry the environment step. OpenCode is downloaded from opencode.ai into Moch Linux; it is not inside the APK.

Moch opens but the model does not answer

Return to Providers. Confirm the provider key or local endpoint, then choose a model. Hosted providers can reject an expired key, an unpaid account or a rate limit.

The runtime stops in the background

Review Android battery restrictions for Moch and keep the runtime process alive. Do not rely on a claim that local work continues after the app process is killed.

I am looking for a QR pairing screen

QR pairing belongs to the legacy v1.0.0 linked/relay flow. The current beta starts with Environment, Thinker, Providers and About you instead.

Legacy v1.0.0 / moch-link relay setup

Existing stable users only. Stable v1.0.0 is a linked/relay-only build. It does not include the embedded runtime or OpenCode, and the current beta does not need this remote pairing path.

The repository still contains the older connector for migration and existing installs. Keep this section separate from the current on-phone recipe.

Show the old linked/relay instructions

1. Link an existing Hermes install

On the Linux machine that already runs Hermes, run the legacy installer. It links the existing install to the relay and prints the pairing code; it does not replace the current beta setup.

curl -fsSL https://moch.softland.tech/install.sh | bash

2. Reprint or check the legacy link

bash install.sh qr
bash install.sh status

3. Pair in stable v1.0.0

Open the stable app, scan the QR code, or use More options to paste the printed hermes://connect… line. Leave the linked machine on and reachable by the legacy relay.

4. Configure the machine-side provider

hermes setup

Manual same-network gateway, advanced

For the older no-relay path, start the Hermes gateway on the machine, then pair from the repository with the machine’s LAN address and gateway port.

hermes gateway setup
hermes gateway start
./scripts/hermes-pair.sh --host 192.168.1.20 --port 8080

If the script asks for a token, use the dashboard session token printed by hermes gateway setup. A saved non-loopback remote gateway from this era is not the current beta runtime path.
